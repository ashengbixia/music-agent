# DeepEval 歌词质量评测

此入口使用 DeepEval 4.3.3 的 GEval，对已生成的真实歌词做离线产物评测。
“离线产物”指读取本地运行记录；正式评分仍会请求 DeepSeek 并产生 API 费用。
它不重新创作、不修改运行状态，也不自动批准歌词或音频。

## 安装和使用

在项目目录、已激活的 music_agent 环境中安装可选依赖：

```powershell
python -m pip install -r requirements-eval.txt
```

先检查输入，不需要密钥，不请求模型（将目录替换为实际运行目录）：

```powershell
python -m music_agent.evaluation --run outputs/run-替换为实际目录名 --dry-run
```

正式评分：

```powershell
$env:DEEPSEEK_API_KEY = "替换为你的密钥"
python -m music_agent.evaluation --run outputs/run-替换为实际目录名
```

可重复传入 `--run`，批量比较不同需求或不同创作配置的运行。
每个运行按 state.json 的 lyrics_file 读取当前版本，包括拒绝后修订的歌词。
报告记录实际文件名与 SHA-256，便于定位被评版本。
默认使用现有客户端的 DEEPSEEK_MODEL 配置；未设置时为 deepseek-flash。

## 指标与报告

- 主题贴合度：主题、主体、核心意象是否落实。
- 风格与情绪：歌词文本是否符合曲风、情绪、语言及受众。
- 歌词表达质量：自然度、连贯性、段落推进及副歌记忆点。

每项记录 0～1 分、通过标志与裁判理由。默认每项至少 0.7 分才通过，
可用 `--threshold 0.8` 修改。阈值是初始配置，需要用人工标注样例校准。
评分步骤固定，每个案例通常发起三次裁判请求；重试可能增加请求数。

JSON 报告默认写到 eval-reports/，包含需求、歌词、评分步骤、裁判模型、
各项分数、通过案例数、调用耗时及接口返回的 token 用量。
可用 `--output 路径` 更改报告目录。全部通过退出码为 0；低分或评分出错为 1。
请求异常单独记为 error_type，score 为 null，不当作质量低分。

本地入口不要求 Confident AI 账号，并默认关闭 DeepEval 遥测。
运行报告包含需求和歌词全文，应按项目资料管理。

## 验证范围

原有 pytest 测试继续验证程序功能与异常恢复；此入口补充模型生成内容的质量评分。
新增集成测试使用真实 GEval 和模拟裁判响应，验证版本选择、分数转换、
阈值、错误报告及原产物不被修改，不产生真实 API 费用。

LLM 裁判有波动和同模型偏差。该评分不能证明原创或版权合规，
也不能评价实际演唱、旋律及编曲效果。当前 mock 音频不纳入艺术质量评测。
目前实现的是歌词质量评测入口；完整端到端基准集、重复采样统计及人工评分校准
仍需继续建设。
