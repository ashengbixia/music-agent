# 本地 Demo 与命令手册

本文覆盖当前 `main.py` 的全部六个子命令及其参数，并补充环境准备、独立 mock、产物查看和测试命令。以下示例使用 **PowerShell**，均在项目根目录执行。

从第 1、2 节开始可完成一次完整演示；第 3～7 节是按需选择的分支和辅助操作，第 8 节是无密钥测试，第 9 节用于查参数。无需从头到尾执行所有代码块。

若使用 CMD 或以 CMD 打开的 Anaconda Prompt，环境变量写法见 [README 配置说明](../README.md#2-配置-deepseek)。本文中的 `$projectId`、`$runDir` 和 `Get-Content` 为 PowerShell 语法，请在 PowerShell 中执行，或在 CMD 命令中直接填写实际项目编号。

完整创作演示需要 DeepSeek 密钥；音频由本地 mock 生成。每次人工审核都应在检查对应产物后单独执行。

## 1. 环境准备

首次创建环境：

```powershell
conda env create -f environment.yml
conda activate music_agent
```

已有环境时更新依赖：

```powershell
conda env update -n music_agent -f environment.yml
conda activate music_agent
```

配置当前终端的密钥与输出编码：

```powershell
$env:DEEPSEEK_API_KEY = "替换为你的密钥"
$env:PYTHONIOENCODING = "utf-8"
```

程序直接读取环境变量，不自动加载 `.env`。需要覆盖客户端默认模型时，可在设置实际可用的模型名称后执行：

```powershell
$env:DEEPSEEK_MODEL = "替换为实际可用的模型名称"
```

演示结束后退出环境：

```powershell
conda deactivate
```

## 2. 主流程演示

使用第二份正常需求单，目标时长 180 秒：

```powershell
$projectId = "song_002"
python main.py run --brief fixtures/briefs/song_002.json
python main.py status $projectId
```

首次成功后应为 `lyrics_ready`。同编号、同需求再次运行会复用已有项目；如项目已存在，先查询状态，再按第 4 节选择后续操作。需要全新项目时，复制 brief 并修改 `project_id`，同时调整上面的 `$projectId`。

### 检查当前歌词

按项目编号获取运行目录，并从状态中读取当前稿件路径，避免把旧稿当成最新版：

```powershell
$runDir = python -c "import sys; from music_agent.storage import find_run_directory; print(find_run_directory(sys.argv[1]).resolve())" $projectId
$state = Get-Content -LiteralPath (Join-Path $runDir "state.json") -Encoding UTF8 | ConvertFrom-Json
Get-Content -LiteralPath (Join-Path $runDir $state.lyrics_file) -Encoding UTF8
```

### 审核歌词，生成作曲方案和音频

确认歌词通过后执行，审核人替换为实际操作人员：

```powershell
python main.py approve --project $projectId --stage lyrics --reviewer "阿圣"
python main.py resume $projectId
python main.py status $projectId
```

成功后应为 `audio_ready`。查看方案、交接清单并试听：

```powershell
Get-Content -LiteralPath (Join-Path $runDir "composition-v001.json") -Encoding UTF8
Get-Content -LiteralPath (Join-Path $runDir "composition-result-v001.json") -Encoding UTF8
Invoke-Item -LiteralPath (Join-Path $runDir "audio-v001.wav")
```

mock 是固定测试音，不包含真实演唱，也不实际呈现编曲效果。

### 审核音频，导出物料包

确认作曲方案和测试音频满足当前流程要求后执行：

```powershell
python main.py approve --project $projectId --stage audio --reviewer "阿圣"
python main.py export --project $projectId
python main.py status $projectId
```

成功后应为 `package_ready`。查看交付目录和运行报告：

```powershell
Get-ChildItem -LiteralPath (Join-Path $runDir "release-package")
Get-Content -LiteralPath (Join-Path $runDir "release-package/manifest.json") -Encoding UTF8
Get-Content -LiteralPath (Join-Path $runDir "run_report.json") -Encoding UTF8
Get-ChildItem -LiteralPath (Join-Path $runDir "model-calls")
```

`release-package/` 应包含 `manifest.json`、`lyrics.md`、`composition.json`、`audio.wav`、`cover.png`、`approvals.json` 和 `README.md`。

## 3. 歌词拒绝与修订分支

此分支从 `lyrics_ready` 开始，与直接通过歌词审核是两种选择。当前拒绝命令只支持歌词阶段。

```powershell
python main.py reject --project $projectId --stage lyrics --reviewer "阿圣" --feedback "增加具体场景，副歌更克制"
python main.py status $projectId
python main.py resume $projectId
python main.py status $projectId
```

拒绝后为 `lyrics_rejected`；恢复成功后，新稿重新进入 `lyrics_ready`，旧稿和拒绝记录保留。重新执行第 2 节的当前歌词读取命令，检查状态指向的新稿，再决定通过或继续拒绝。

## 4. 按状态继续与失败重试

先查询状态：

```powershell
python main.py status $projectId
```

| 当前状态 | 下一步 |
| --- | --- |
| `new` | 计划或歌词生成未完成，执行 `resume` 恢复。 |
| `lyrics_ready` | 检查当前歌词，然后选择 `approve --stage lyrics` 或 `reject --stage lyrics`。 |
| `lyrics_rejected` | 执行 `resume`，根据反馈生成或恢复修订稿。 |
| `lyrics_approved` | 执行 `resume`，生成或恢复作曲方案及音频。 |
| `audio_ready` | 检查作曲方案和音频后，执行 `approve --stage audio`。 |
| `audio_approved` | 执行 `export`。 |
| `package_needs_info` | 修正缺项或校验错误后，再次 `export`。 |
| `package_ready` | 可以再次 `export` 校验并复用已有包。 |

创作失败或创作过程中断后重试：

```powershell
python main.py resume $projectId
```

打包失败或打包过程中断后重试：

```powershell
python main.py export --project $projectId
```

恢复时会核对版本、输入和哈希。文件或输入发生冲突时，应先查明原因，不能靠反复重试绕过检查。当前不支持音频审核拒绝重制。

## 5. 指定运行目录：--run

同一项目匹配多个运行目录时，使用实际目录名明确选择，例如 `run-xxxxxxxx`，不传完整路径。将下面的占位值替换后，按当前状态选择一条命令执行，不要整段批量执行审核操作。

```powershell
$runId = "run-替换为实际目录名"
python main.py status $projectId --run $runId
python main.py resume $projectId --run $runId
python main.py approve --project $projectId --stage lyrics --reviewer "阿圣" --run $runId
python main.py approve --project $projectId --stage audio --reviewer "阿圣" --run $runId
python main.py reject --project $projectId --stage lyrics --reviewer "阿圣" --feedback "补充具体场景" --run $runId
python main.py export --project $projectId --run $runId
```

此时读取产物也应使用同一个目录：

```powershell
$runDir = python -c "import sys; from music_agent.storage import find_run_directory; print(find_run_directory(sys.argv[1], sys.argv[2]).resolve())" $projectId $runId
```

`run` 创建或复用项目，不接受 `--run` 参数。`--run` 用于已有项目的操作，不能用于指定新运行目录。

## 6. 三份原始需求样例

以下是独立运行示例，不属于第 2 节必须连续执行的步骤：

```powershell
python main.py run --brief fixtures/briefs/song_001.json
python main.py run --brief fixtures/briefs/song_002.json
python main.py run --brief fixtures/briefs/song_003.json
```

- `song_001`：毕业告别、流行摇滚、210 秒。
- `song_002`：鲲游向天空、国风电子、180 秒。
- `song_003`：异常样例，应在请求模型前失败。原始样例首先报告缺少受众；补齐后仍有时长及主平台冲突。

程序成功退出码为 `0`，业务失败为 `1`，命令行参数错误由 argparse 返回 `2`。PowerShell 可在命令执行后用 `$LASTEXITCODE` 查看退出码。

## 7. 独立本地 mock

不需要 DeepSeek 密钥或单独启动服务：

```powershell
python -c "from music_agent.clients.mock_music import generate_audio; print(generate_audio('outputs/mock_demo.wav', 3))"
```

生成 3 秒、22050 Hz、单声道、16 位 PCM WAV，返回音频参数和哈希。目标存在时拒绝覆盖，再次演示请换一个输出文件名。

检查已经生成的测试音：

```powershell
python -c "from music_agent.clients.mock_music import inspect_audio; print(inspect_audio('outputs/mock_demo.wav', 3))"
```

## 8. 无密钥模拟演示与自动化测试

测试数据来源、各测试文件职责及结果解读见 [README 自动化测试](../README.md#8-自动化测试)。

以下测试全部使用模拟接口与临时目录。测试内的审核为流程模拟，测试产物不作为保留的交付示例。

两份正常需求单的完整模拟流程：

```powershell
python -m pytest tests/test_acceptance.py -k normal_brief_complete_workflow -v -s
```

CLI 完整流程：

```powershell
python -m pytest tests/test_review_gates.py -k cli_complete_workflow -v -s
```

打包中断恢复：

```powershell
python -m pytest tests/test_packaging.py -k recovers_after_crash -v
```

全部验收测试与完整测试集分别执行：

```powershell
python -m pytest tests/test_acceptance.py -q
python -m pytest tests -q
```

最近一次完整测试为 202 项通过。若只想查看测试列表而不执行：

```powershell
python -m pytest tests --collect-only -q
```

## 9. 六个子命令及全部业务参数

| 子命令 | 必需参数 | 可选参数 |
| --- | --- | --- |
| `run` | `--brief`：JSON 需求单路径 | 无 |
| `status` | 位置参数 `project_id` | `--run` |
| `approve` | `--project`、`--stage`（lyrics 或 audio）、`--reviewer` | `--run` |
| `reject` | `--project`、`--stage lyrics`、`--reviewer`、`--feedback` | `--run` |
| `resume` | 位置参数 `project_id` | `--run` |
| `export` | `--project` | `--run` |

全部命令支持 `-h` 或 `--help`。查看帮助不会请求模型或创建项目：

```powershell
python main.py --help
python main.py run --help
python main.py status --help
python main.py approve --help
python main.py reject --help
python main.py resume --help
python main.py export --help
```

安装配置及实现边界见 [项目 README](../README.md)，AI 分工见 [AI 使用说明](AI%20使用说明.md)。
